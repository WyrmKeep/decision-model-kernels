Reports: p3-ncu-smoke-a.ncu-repz, p3-ncu-smoke-b.ncu-repz, p3-ncu-core-long-p0.ncu-repz, p3-ncu-core-long-p1.ncu-repz, p3-ncu-core-long-p2.ncu-repz, p3-ncu-core-mv.ncu-repz, p3-ncu-core-short-p0.ncu-repz, p3-ncu-core-short-p1.ncu-repz, p3-ncu-extra-long-att.ncu-repz, p3-ncu-extra-long-ew.ncu-repz, p3-ncu-extra-long-full.ncu-repz, p3-ncu-extra-long-p4.ncu-repz, p3-ncu-extra-med-p0.ncu-repz

Limits of the RTX 3060 Ti used for the floors (card measurements quoted in the task context, not re-measured here):

| limit | value |
|---|---|
| DRAM read bandwidth, GB/s | 422.0 |
| int8 tensor (mma.sync, dense), TOP/s | 149.3 |
| fp16 tensor with fp32 accumulate, TFLOP/s | 38.0 |
| fp32 CUDA cores, TFLOP/s | 18.1 (census_lib.FP32_TFLOPS) |
| launch floor, us | 1.0 (shortest kernel of the 13 nsys-traced passes: 0.992 us) |

Source: ncu_cfg.py.

Time at the limit = max(model bytes / DRAM bandwidth, useful int8 ops / int8 peak, fp16 flops / fp16 peak, fp32 flops / fp32 peak, launch floor). Model bytes = all tensors of the kernel from/to DRAM (weights + q8_1 input + f32 output for a matmul): cold-cache numbers, which is what `--cache-control all` measures. The binding limit is the one with the largest time; kernels without a byte model use the measured DRAM bytes. 'Gap' = measured - time at the limit; 'per pass' multiplies it with the launches of the class in one pass (census). A kernel that cannot reach its floor for structural reasons (e.g. gdn_single: 32 CTAs, serial chunk loop) still shows the gap; read the stall columns.
